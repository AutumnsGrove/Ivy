breaking the runner makes it fail and shrink. This note records the runner, the schema that came with
it, the tests that had to move for it, and what 3a still owes. It is written for a fresh reviewer:

## 3. What the runner does (`sync/sync.go`)

`Fetcher.Fetch` is now the runner (the harness seam `oneShotFetch` calls it unchanged). One pass:

1. `SweepSpool`, `EnsureAccount`, `dial`, then `fetchAll` on one connection.
2. **Snapshot every selectable mailbox** (`snapshotFolder`): SELECT read-only, then one metadata
   FETCH (`UID`, `FLAGS`, `ENVELOPE`, `INTERNALDATE`, `RFC822SIZE`) of `1:*`. The whole account is
   read before anything is written, so a message that moved between folders can be told apart from
   one that was removed. Bodies are not read here.
3. **Reconcile each folder** (`reconcileFolder`): upsert the folder row first (it revives a name the
   server has brought back), read the live `SyncMessageRef`s, then
   - refresh flags of mirrored rows only when they differ (`SetMessageFlags`, narrow: no content
     key, no raw bytes, no derived data);
   - disable a mirrored row the server no longer holds, reason `moved` when its Message-ID is still
     somewhere on the server and `server_removed` otherwise;
   - fetch the missing bodies newest-first, in batches of `WithBatchSize` (`f.batch`), re-selecting
     the folder before each `fetchBatch`.
4. **Mark folders gone** (`markGoneFolders`): a folder the server no longer lists gets `gone_at` and
   its live messages are disabled with the same move/removed rule. Nothing is deleted.
5. `Settle` (re-derive + thread) as before.

`Result.Skipped` counts messages the mirror already held. A UIDVALIDITY change disables the old
validity's live rows with the move/removed reason, then reads the new validity as if new.

Moving a message updates no existing row except to disable it: the new row keeps its own id, so the
disabled row (and its bytes) stays. Flags are compared case-insensitively and order-insensitively
(`canonicalFlags`/`sameFlags`).

## 4. Schema that came with the runner

Migration 9 (`store/migrations.go`) is append-only:

- `folders.gone_at` (TEXT, null when live). `ListFolders`/`AllFolders` distinguish live from gone;
  `UpsertFolder` clears `gone_at` on conflict so a recreated name revives the same row.
  `SetFolderGone` is idempotent.
- `messages.uidvalidity` plus `UNIQUE(folder_id, uidvalidity, uid)`. SQLite cannot drop the old
  `UNIQUE(folder_id, uid)` in place, so the table is rebuilt. A rebuild cannot run with foreign keys
  enforced (the old `messages` is dropped while `attachments` references it) and the pragma cannot
  change inside a transaction, so `migrate` now turns the write connection's foreign keys off for a
  pending run, runs every migration, re-enables them and then runs `PRAGMA foreign_key_check`. Every
  id is copied, so the child rows stay valid. `TestMirrorUpgradeFromEveryPriorVersion` now seeds an
  `attachments` row from v2 on, which is what caught the first two attempts (they failed at commit
  and mid-migration respectively).
- The message id is `messageRowID(folderID, uidvalidity, uid)` and the spool path is
  `spool/<folderID>/<uidvalidity>/<uid>.eml`, so a server that reuses an old UID after a rebuild
  cannot collide with the disabled row's id, unique key or file. The old row keeps its bytes.
- `store.DisableMessage`, `store.SetMessageFlags`, `store.SyncMessageRefs` (light projection,
  no body) and `store.AllFolders` are new.
- The fast dev seeder keeps up: `mailworld.Delivery` now carries `UIDValidity`, read once per
  mailbox by the seed observer and passed to `Fetcher.StoreRaw`. `TestFastAndFullAgreeForDemo`
  compares every column including `uidvalidity`, so the two modes stay byte-identical.

The disabled reason string is now fixed: `server_removed` (round 38), matching the oracle's check 4.

## 5. Tests that moved (and why)

These are mechanical or self-test changes, not relaxations of the convergence oracle:

- `sync/sync_test.go`, `TestFetchNewestFirstAndResumes`: the drop count moves from 6 to 8. The runner
  adds a whole-account metadata pre-pass, so the 8th command is the next message's SELECT and the
  newest message is already the checkpoint. The assertions (partial `[5]`, resume `4 stored / 1
  skipped`, no duplicates) are unchanged.
- `sync/storeraw_test.go`: `StoreRaw` gained the `uidvalidity` parameter.
- `sync/converge_test.go`: the stale-flags self-test now uses `staleFlagSync` (section 2) instead of
  relying on the chunk 2b fetch being wrong. The oracle and generator are untouched.

## 6. What is not here (open for 3a before it is called done)

- **QRESYNC/CHANGEDSINCE and IDLE are not implemented.** Both harness variants currently take the
  full-scan fallback, which is why the condstore and no-condstore mixes are identical. The runner is
  correct but a full account rescan every pass is not the steady state the brief describes. The
  snapshot/reconcile split was chosen so `folderSnapshot` can later be fed by a CHANGEDSINCE delta and
  a `VANISHED` set; that is the next slice.
- **`sync_state` is not written by the runner.** The table and `SetSyncState`/`GetSyncState` exist
  (round 38 groundwork), but nothing calls them yet.
- The frontend `EventSource` client in `web/src/lib/api/` is still open (C1 note).
